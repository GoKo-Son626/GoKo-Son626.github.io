一个常见需求

两个客户端都要读取设备参数：A 查询温度，B 查询电压。服务端接收请求，调用设备接口，再把结果分别返回。即使通信发生在同一进程中，也可以用 SB 的发布订阅来组织这条路径。

发送请求并不是调用服务端函数，也不表示发送函数会等待设备读取完成。客户端发送后，需要等待自己的回复管道，并检查收到的消息属于哪个请求。

请求与回复携带什么

后续演示的客户端在建立自己的回复 Pipe 后，为每轮请求填写下面几个字段。摘自 rpc_demo.c，省略设备号和参数号的赋值。

client_id 标记业务客户端，key 区分同一客户端的不同请求，reply_msgid 告诉服务端往哪个 SB 主题发回结果。A、B 在同一轮可以使用同一个 key，因为它们各有自己的回复 MsgId 和 Pipe。设备读取结果用 status 和 value 表示，设备不存在或参数无效时仍可收到错误回复，不能把错误回复里的 value = 0 当作测量值。

为什么要测试逆序回复

并发请求不保证回复顺序等于发送顺序。服务端可以先收集两条请求，再按实际到达的逆序处理；客户端应根据关联字段匹配，而不是认为“第二条回复一定对应第二条请求”。如果一个客户端允许多个请求同时在途，还需要维护待处理请求表，并设计超时、重试、重复响应和编号回绕策略。单客户端一次只发一个请求的演示并未覆盖这些情况。

服务端在核对 MsgId、长度和功能码后，把载荷复制到自己的数组。它可以继续接收下一条请求，然后倒序处理数组中的副本。

这次复制保留了请求内容。下一次 CFE_SB_ReceiveBuffer() 可能归还上一条 SB 缓冲，处理顺序不能依赖旧缓冲指针。

标准模式、EDS 和传输的边界

历史 RPC 演示是同一地址空间的三个业务任务，没有经过 SBN 或网络。其 EDS 分支还对请求和响应执行额外编解码往返检查，但实际 SB 发送仍是本地消息；打包缓冲并未由此自动成为网络载荷。

历史文档记录了五次请求、五次回复、一次逆序处理和两个空管道超时的有限测试，标准和 EDS 的本地头部大小不同。这些数据属于当时的构建配置；这个实验不代表持续运行的服务，也不证明跨节点、跨 ABI 或异常网络环境下的可靠 RPC。

回复发给谁，怎样认出自己的回复

服务端使用请求中的 reply_msgid 初始化回复头，并回填 key 和业务字段。演示使用预先约定的客户端和回复主题。若服务要接收其他来源的请求，应在发送前按接口约定检查该客户端允许使用哪些回复主题。

问题 固定回复主题 请求携带回复主题
服务端怎样选择回复端点 根据配置或客户端映射 从请求取出，服务端按约定校验
配置代价 服务端需知道对应关系 客户端提供端点，服务端需约束合法性
请求怎样关联 客户端身份与请求编号 回复端点、客户端身份与请求 key 等

MsgId 决定路由，关联键决定某条回复属于哪次请求，业务字段决定回复是否符合预期。这三层检查缺一不可。把收到的每一条回复都按当前请求解析，会在迟到包到达时产生隐蔽错误。

迟到回复不会刷新超时

客户端用单调时钟计算一次截止时间。在 wait_reply() 中，每次循环都用同一个截止时间求剩余毫秒数。以下摘录省略时钟和接收错误的一部分处理。

例如 150 ms 的预算已用去 100 ms，丢弃旧 key 后下一次只等剩下的 50 ms。原实现取到包后还会刷新时钟，再检查一次截止时间。等待超时只终止客户端对这次回复的等待，服务端的设备操作需要独立的取消机制。

把成功响应、设备错误和传输失败分开

设备返回错误但完整响应已收到，属于“通信成功，业务失败”；等待超时表示本次预算内没有得到可接受响应，不能反推设备错误码。返回值为 0 也只有在 status 成功且单位已约定时才是有效测量。

测试至少应包括单客户端、并发逆序、设备错误、请求超时和迟到响应；还要确认清理流程不会让其他任务继续访问已删除 Pipe 的缓冲。历史文档的五次请求结果与当前源码里预期的九次请求计数属于不同阶段，文章不把后者写成本轮已经运行通过的结果。

用阶段表检查业务约束

阶段 输入 应观察的结果
单客户端 A 读设备 7 的温度参数 状态成功，单位为毫摄氏度，示例值 25000
并发逆序 A 读温度，B 读电压 回复顺序可逆，字段仍与各自请求匹配；电压示例为 3300 mV
设备错误 设备 99 或参数 99 收到完整错误响应，而不是把值 0 当测量结果
请求超时 服务端暂缓响应 客户端在预算内退出等待
迟到响应 新请求期间收到旧 key 旧回复被丢弃，剩余预算不重新开始

这张表组合了演进后的测试目标，不代表早期五请求版本已经包含后两阶段。后续 CI/TO 历史验证记录给出了九请求、九回复、匹配七次、超时四次、丢弃两次的结果；其中超时包含两次业务等待和两次空管道检查。原 Word 记录的五请求结果应另行阅读，不能把两者当成一次执行。

设备接口只接收设备号、参数号和结果地址，不依赖 SB Pipe。服务端负责把状态和关联字段装回消息，客户端负责按契约校验。这种分工允许将来替换设备驱动，而不把消息总线细节带进驱动。

前置机制可对照订阅与管道、接收缓冲区。
